# NEXI Platform User and Admin Operations Guide

**As of:** 2026-11-04
**Source basis:** current repository HEAD 2a74ce1b60940221ddb53f95baf4ec04a1f6eac4; route/provider contracts in Admin/src and backend source. **Runtime is separate:** current Backend and Public release marker 188fdba1b9e703f04f1c3fbe32186f7daa6dce22; current Admin release marker 111a5010f04a6592c290b0b0bc93240ab0cec69b. This guide describes source-backed intent; browser acceptance and live persisted configuration are recorded separately in tasks/evidence/nexi-browser-acceptance-v2-20261104.md.
**Authority:** NestJS owns business decisions; promoted VPS SQLite/Prisma owns durable state; Ledger/Activity and EventOutbox/EventInbox prove financial accounting and durable publication. BullMQ with Aiven Valkey transports async jobs; Socket.IO Redis Streams/Valkey transport realtime and cache. Neither Valkey nor BullMQ is financial truth. Cloudflare Worker/Container/D1/Queues/Workflows are retired runtime. Do not infer runtime from source or release SHA alone.

## Public customer journeys

- **Sign in:** Public uses wallet-based SIWE. Identity and session status are established by the API. A signature is an authentication action; never read wallet secrets or approve a prompt whose origin, chain, account, nonce and message are not expected.
- **Quotes and Asset Detail:** Dashboard is the Quotes Hub; Asset Detail is /dashboard/asset/[symbol]. Instruments and wallet-depositable assets are different catalogs. Show provider source and freshness; historical metadata may be partial. Asset Detail links into Spot/Margin and Options.
- **Spot and Margin:** /dashboard/spot contains chart/timeframes, reference order book/trades, Spot and Margin panels, order controls and account history. Provider order book/trades are reference liquidity, not executable NEXI orders. Orders, reservations, fills, fees and margin liabilities require authorized account state and durable Ledger/Activity evidence.
- **Options:** /dashboard/binary is directional Binary Options, not staking. Pair/duration/payout/stake values come from Backend/Admin authority. The BINARY account is distinct from MAIN/Funding, SPOT, MARGIN and FINANCE. Disabled insufficient-balance states must explain a valid Wallet recovery path.
- **Wallet:** /dashboard/wallet separates Overview, Funding, Spot, Margin, Options and Finance. Supported depositable assets are not the full 53-instrument market catalog. Transfers conserve the selected asset between eligible accounts; conversion is a separate quoted operation. Activity should reconcile to authoritative Ledger postings and backend status. No direct balance edits.
- **Products and communications:** /dashboard/mining and /dashboard/loans reflect backend eligibility and lifecycle. Messages and Support remain distinct: Public Support help/contact is not retired Admin tickets; the active customer conversation maps to Admin Messages. Announcements and Learn are published content; notifications are user scoped.
- **Mobile contract:** Public is mobile-first, 320px+ with usable chart touch/focus, five-destination dock, safe-area handling and short-height recovery. Browser emulation and physical-device notch proof are separate.

## Admin operator contract

Admin is a desktop-first TanStack/React control plane. Eight workspace groups expose 31 role-filtered sidebar destinations; contextual /sandbox is the 32nd functional destination. Retired /support is compatibility-only; hidden /reconciliation has no active canonical reconciliation writer. Navigation visibility is not backend authorization. Routes use the configured live NexiAdminApiProvider; its route guard and server-side NestJS permissions govern access. The table distinguishes UI/API source contracts from actions exercised in browser acceptance.

For all routes, normal states are current provider data; a valid empty result is a normal empty state; loading and provider errors must stay distinguishable; unauthorized roles receive a guard/403 state. Exact counts and persisted values below are not promises. Reason, actor, permission, confirmation and approval are required where route/provider contracts specify a consequential command. Do not operate those commands during read-only acceptance.
