# Backend development dependency advisory reachability — 2026-10-27

## Scope and method

Read-only review of `backend/package.json` and `backend/package-lock.json` at source HEAD `ed1c574a754b60fd292f60374c8d7b405b9a3202`. Toolchain observed: Node `v24.21.0`, npm `11.19.0`. Ran a full `npm audit --json` against the committed lockfile and mapped each reported node to its lock entry. The full audit returned 24 findings: 1 critical, 14 high, 7 moderate, 2 low. All 15 critical/high affected lock entries in this review have `dev: true`; none is a production dependency entry. Searched `backend/src`, `backend/scripts`, and package scripts for the affected modules and inspected the relevant script boundaries. No affected package is imported by backend application source. `prisma` is an explicit dev dependency; the other affected entries are transitive development/tooling dependencies. Handlebars is reached through the `ts-jest` development/test chain (`npm explain handlebars --json`). Prisma tooling is invoked by the `pretest` script (`prisma generate`); it is not the `start:prod` entry (`node dist/src/main.js`).

This is source/lockfile reachability evidence only. The shared physical dependency store can contain dev packages; this review does not prove that every deployed artifact or runtime filesystem excludes them. It also does not prove that vulnerable APIs are unreachable inside the packages' own test/build code. No install, build, source edit, runtime inspection, or production operation was performed.

## Disposition and limits

All 15 critical/high findings are verified as vulnerable **development/tooling** lock entries at the exact versions above; no affected module call path was found from NEXI production application source. This is not a claim that development tooling is risk-free: running tests, Prisma generation, configuration, lint, or other dev commands executes dependency code, and the physically shared dependency store may retain dev packages. Several advisories have compatible upstream patches, while resolving Prisma aggregates can require updating the Prisma tooling dependency graph. This lane made no dependency change. Review/install of an updated lockfile, clean artifact contents, and production runtime reachability remain outside this source-only evidence report.

Official sources are the linked GitHub Advisory Database records; package-specific affected and patched ranges are quoted in the rows above. As an example of the relevant Handlebars precondition, GitHub's advisories state that the AST issue requires an untrusted AST/object passed to `compile`/`precompile`, and the own-property issue requires the documented prototype-method allowance; neither API path was found in NEXI application source.
