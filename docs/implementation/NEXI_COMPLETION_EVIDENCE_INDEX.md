## Purpose
Provide a durable index to evidence locations without embedding secrets or treating evidence references as self-validating.

## Evidence categories
Authority/decisions; current-state inventory; route artifacts; changed-file ledgers; contract/schema versions; lint/type/build; unit/integration/contract/database/WS tests; runtime/API health; browser screenshots/console/network; authorization/security; ledger/reconciliation; observability/alerts; migration/backup/recovery; deployment/rollback; independent reviews; approval records.

## Required entry fields
Evidence ID, phase/slice, claim, state proved, source path or command, timestamp, environment, actor/tool, result, limitations, linked issue/risk, reviewer, and superseded-by reference.

## Storage policy
Text reports belong under `work/<dated-scope>` or stable `docs` summaries; generated test/build artifacts use their tool-standard locations; screenshots use a named evidence directory; secrets and raw credential-bearing logs are excluded.

## Status discipline
Configured, discovered, trusted, authenticated, callable, invoked, completed, and verified remain separate. An index entry may point to evidence but cannot upgrade its state without direct validation.

## Evidence and completion rule
Keep `specified → implemented → statically validated → tested → integrated → runtime verified → browser verified → security reviewed → independently reviewed → approved complete` distinct. File presence, plans, generated graphs, and passing static checks alone are not completion.
