## Static HTTP contract reconciliation

The full `docs/contracts/openapi.json` parsed as OpenAPI `3.0.0` with 234 paths, 256 operations, and 95 schemas. The route inventory compared HTTP method and normalized path only; it did not exhaustively compare request DTO fields, response schemas/fields, client error handling, or runtime behavior.

- All 256 documented method/path operations matched a current Backend controller method/path pair after normalizing Nest `:param` and OpenAPI `{param}` syntax.
- Four additional Backend controller routes were not present in OpenAPI and had no Public or Admin caller in the checked source: `POST /lever/deal`, `POST /lever/setstop`, `POST /lever/close`, and `GET /lever/my_trade` (`backend/src/contract/contract.controller.ts:26,53,67,79`). This is an undocumented/unconsumed route surface; the static check does not establish whether those routes are intentionally private, legacy, or externally consumed.
- The bounded Public scan found 34 unique statically identifiable literal/template API calls; each mapped to a documented Backend route/method. Examples: wallet overview/activity at `frontend/app/dashboard/wallet/page.tsx:198` map to `GET /wallet/overview` and `GET /wallet/activity`; Spot history/book/trades/orders at `frontend/app/dashboard/spot/page.tsx:137,191,202,681` map to documented `/spot/*` operations; transfers and Support messages also map to documented controller operations.
- The bounded Admin provider scan found 52 identifiable API paths with no literal endpoint mismatch. The conditional approve/reject route was manually checked at `Admin/src/admin/data/nexi-api-provider.ts:2368-2381` against OpenAPI and `backend/src/admin/admin.controller.ts:297,312`. UI navigation paths were excluded from API mismatch counts.
- Backend controller/service/store mapping follows the current architecture: NestJS controllers and guards delegate to domain services; Prisma 7 / promoted SQLite is the durable application authority; Ledger and EventOutbox/Inbox/journals remain the financial and durable-event authorities; Valkey/BullMQ/Socket.IO remain transport. Direct source confirms `D1PrismaService` constructs the Prisma better-sqlite3 adapter from `NEXI_LOCAL_SQLITE_PATH` (`backend/src/d1/d1-prisma.service.ts:43-51`), `D1WorkerBridgeModule` binds the compatibility token to `LocalSqliteBridgeService` (`backend/src/d1/d1-worker-bridge.module.ts:8-13`), and `WalletService` reads through `D1FinancialCommandGateway` (`backend/src/wallet/wallet.service.ts:40-45`). The `D1*` class names are compatibility names, not evidence of a Cloudflare runtime. These source declarations do not substitute for checking the live configured database path or runtime contents.

## Documentation gap: security metadata

`docs/contracts/openapi.json` has no global bearer-security default. Current protected Backend operations such as `GET/PATCH /auth/me`, auth preferences/sessions/security status, financial operations, and multiple protected Admin communications operations have Backend JWT/surface/permission guards but lack matching OpenAPI operation security declarations. `GET /communications/admin/messages` does declare bearer security, so the whole communications family is not uniformly missing metadata. Some routes in the same tags are intentionally public; reconcile each operation rather than adding a blanket global requirement. This is an API-documentation gap, not evidence that runtime authorization is absent or bypassed. The generated contract/source annotations should be reviewed before editing the checked-in OpenAPI artifact.
