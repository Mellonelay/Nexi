# **Dexi Style: Technical Architecture & Product Specification**

**Date:** April 1, 2026  
**Status:** Stakeholder Review Draft  
**Version:** 1.0  

---

### **Executive Summary**
The Dexi Style platform is a high-performance, mobile-first cryptocurrency exchange ecosystem designed to provide professional-grade financial tools in an accessible web environment. By integrating low-latency trading engines with structured wealth management products (Mining, Loans, and Conversion), the platform offers a comprehensive lifecycle for digital asset management.

Key outcomes of this architecture include:
- **Instant Settlement**: A real-time micro-trading engine for binary options.
- **Deep Liquidity Mocking**: Spot trading interfaces mirrored from production environments.
- **Automated Wealth Distribution**: Passive income generation via programmable mining plans.
- **Security-First Compliance**: Tiered KYC and administrative risk controls.

---

### **1. Product Ecosystem & Core Modules**

#### **1.1 Spot Trading Engine**
The Spot module enables direct exchange of assets with order book depth and real-time ticker updates.
- **Technical Implementation**: Utilizes [spot.service.ts](file:///c:/Users/Mr%20Thomas/Documents/trae_projects/Dexi%20style/backend/src/spot/spot.service.ts) for order matching and [spot.gateway.ts](file:///c:/Users/Mr%20Thomas/Documents/trae_projects/Dexi%20style/backend/src/spot/spot.gateway.ts) for live data broadcasting.
- **Data Model**: Tracks `OrderSide` (Buy/Sell), `OrderType` (Limit/Market), and `OrderStatus` (Filled, Canceled, Partial).

#### **1.2 Microtrade (Binary Options)**
A high-frequency speculation engine allowing users to open fixed-duration positions on price movements.
- **Real-Time Settlement**: Managed by a 1-second interval scheduler in [binary.service.ts](file:///c:/Users/Mr%20Thomas/Documents/trae_projects/Dexi%20style/backend/src/binary/binary.service.ts).
- **Settlement Logic**: Automatically compares `entryPrice` vs `closePrice` at expiry to calculate `realizedProfit` based on a configurable `payoutRate` (typically 85%).

#### **1.3 Wealth Management (Mining & Loans)**
Structured financial products for long-term growth and capital efficiency.
- **Mining Plans**: Users subscribe to plans with defined lockup periods and daily yields. Automated by cron jobs in [mining.service.ts](file:///c:/Users/Mr%20Thomas/Documents/trae_projects/Dexi%20style/backend/src/mining/mining.service.ts).
- **Credit Facilities**: A loan module supporting applications, manual administrative review, and instant disbursement to the user’s [Wallet](file:///c:/Users/Mr%20Thomas/Documents/trae_projects/Dexi%20style/backend/prisma/schema.prisma#L45-L53).

### **2. Technical Architecture**

#### **2.1 Backend: NestJS Monolith**
The backend is built on a modular NestJS framework for maintainability and scalability.
- **Authentication**: JWT-based stateless authentication with role-based access control (USER, ADMIN).
- **ORM**: Prisma provides type-safe interactions with the PostgreSQL database.
- **Concurrency**: Real-time updates for prices and orders are handled via Socket.io.

#### **2.2 Frontend: Next.js 14 (App Router)**
A mobile-first H5 application built with Tailwind CSS and Framer Motion for a native app-like experience.
- **State Management**: Lightweight React hooks (`useState`, `useEffect`) combined with real-time Socket.io listeners.
- **Charting**: Integration of `lightweight-charts` for professional TradingView-style technical analysis.

#### **2.3 Database Schema Highlights**
The [schema.prisma](file:///c:/Users/Mr%20Thomas/Documents/trae_projects/Dexi%20style/backend/prisma/schema.prisma) defines a robust financial ledger:
- **Ledger Integrity**: Every balance change is recorded in the `Ledger` table with a `LedgerType` (Deposit, Withdrawal, Trade, Mining, etc.).
- **Multi-Currency Support**: Balances are stored as a JSON object in the `Wallet` model to support dynamic asset additions without schema migrations.

### **3. Security & Risk Management**

#### **3.1 KYC Verification**
A tiered identity verification process managed through [kyc.controller.ts](file:///c:/Users/Mr%20Thomas/Documents/trae_projects/Dexi%20style/backend/src/kyc/kyc.controller.ts). Admins can review document uploads and approve/reject status, directly impacting user withdrawal limits.

#### **3.2 Administrative Overrides**
The platform includes an "Obsessive Risk Controller" interface:
- **House Win Ratio**: Admins can set specific win probabilities per pair to manage platform profitability.
- **Forced Result**: Capability to manually override position outcomes (Win/Loss/Draw) for individual users via the `forceOutcome` flag in the [User](file:///c:/Users/Mr%20Thomas/Documents/trae_projects/Dexi%20style/backend/prisma/schema.prisma#L10-L24) model.

### **4. Actionable Recommendations**

1.  **Scalability**: Transition high-frequency binary settlement logic from the main application thread to a dedicated worker service (Redis/BullMQ) to prevent API latency during peak trading.
2.  **Auditability**: Implement an `AdminAuditLog` for all balance overrides and forced result actions to maintain platform transparency.
3.  **Liquidity**: Integrate real-time price feeds from external aggregators (e.g., Binance API) instead of mocked data to ensure production realism.
4.  **Security**: Introduce 2FA (Two-Factor Authentication) using TOTP (Google Authenticator) as a mandatory requirement for withdrawals.
